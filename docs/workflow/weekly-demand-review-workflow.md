# 周工作平面需求大表评审工作流（R6·2026-10-14 CEO 15:58 批立）

## 一、定位与来源

- 令源：CEO 2026-10-14 15:30 组织流程七点叙事定谳点 1（BOD 15:31:48 转达）+15:58 批 R1-R7 全批（七点核对卷=树卷 `bod-whitepaper-meta-narrative-20261014`）——周工作平面需求大表·周日 12:00 评审在册化（点 1 系全新缺口，本件即落点）。
- 定性：公司级周节律工作流——**需求大表积累 → 周日 12:00 评审 → 真实需求筛出 → PRD+任务书产出 → 流转面研发执行** 五段闭环。

## 二、五段流程

1. **需求大表积累（周内滚动）**：周工作平面需求大表持续积累——来源=周工作任务/产品需求说明书/席间提案/CEO 目标；登记位=operating-records 当前周目录（COS 收口域）。
2. **周日 12:00 评审**：评审会核对需求大表——筛真实需求（去重/降级/否决留痕），产出=真实需求清单；会议纪要归 operating-records 归档（秘书处制度，CAO 收口）。
3. **PRD+任务书产出（评审后当日）**：真实需求逐条落 PRD（CPO 面）+任务书——任务书来源=产品需求说明书或周工作任务，COS 与 COO 据此拆出（contract v4.2 R2 同源口径）。
4. **流转执行**：COS 交单→COO 拆树派工（D-27 v4）；任务树=任务书拆解到 agent 和人的一条或多条协作链（contract v4.2 R3 同源）；FADE 型任务免拆直执（D-27 v6）。
5. **验收销账**：树协议收尾归 COS；销账必附树路径+收口报告指针（D-27 条 2 机械凭证）。

## 三、与周日 23:00 周平面迁移的时序衔接

- 同日双节律不冲突：**午 12:00 评审成件**（PRD+任务书赶在迁移前挂平面）→**夜 23:00 周平面迁移执行**（执行点=河源 TriRMC cron，周平面迁移执行点真源另册）——评审成件随平面平移落地。
- 12:00 评审未成件的需求留大表滚入下周，不阻塞 23:00 迁移。
