### 头栏补则（M1 现役栏并入·M2 增）

- **执行域栏（强制）**——M1 §二制度全文保留：
  1. **枚举（四控制器域名）**：`TriMMC / TriMLC / TriRMC / TriRLC`。
  2. **三律**：**机器=域的实例，禁机器名当域名**——执行域栏只写域名字面（如 `TriMMC`），不写 sg/R-HY/机位/IP 等机器名；机器落点（哪台机哪个实例）属施工细节，入「二、拆树表」施工位列或「四、边界护栏」栏。**TriRLC 过渡注记**：TriRLC 本机暂挤 M 面本地域运行、未来分开（CEO 2026-10-07 11:06 裁正口径）——涉 TriRLC 任务执行域照写 `TriRLC`，机器面现状不改变域名归属。**跨域任务列全值**，主执行域在前。
  3. **禁空栏**：执行域无值=模板不合格，CHO 字段抽查即记。
- **按需增补栏（M1 现役·有则写）**：`挂账号`（LG 号候授/已授）/`face 路由`（会话实体/制度/施工/验收分工）/`立书位`（董事会 BOD/席位面——与「形成位」并存各记：立书位=令源侧定位，形成位=起草席落款）。
- **栏名换代映射**：M1「受理依据」栏由 A1「令源」栏取代（令面+锚功能并入，令文原话锚更全）；M1 旧栏结构四节由六段取代——目标形态→一目标与范围；节点+验收锚→二拆树表（施工位/门禁毕锚列）；边界与纪律→四边界护栏。

## 四、过渡映射（M1 制度保留·server-executable 兼容期）

- `face=server-executable`（树协议夜航01 形态 2026-09-14 起现役旧标注）=「非本地域执行」标注面；四域名=新正形（具体化到控制器域）。
- 映射：`server-executable` ⇒ 执行域 ∈ {TriMMC, TriRMC}（具体归属以树 `tree-op.json` domainRouting 字段为准）；本地域任务旧形态无该标注（原缺省=本地域）⇒ 执行域照实写所属域。
- 兼容期约定三条：①在途/历史任务书**不追改**（原标注继续可读）；②新任务书自本版起一律带执行域栏（`face=server-executable` 标注不再新写，过渡期由执行域栏取代）；③Qualify 机械资格门三重门中的 server-executable 判据（fade-registry §Qualify）**保留不动**——资格门是机械判据面，与执行域栏（标注面）并行各司其职，禁混消。

## 五、登记面 schema（FADE-008 v3·CEO 17:02 五决随窗落·M2.x 增）

- **charter-id**：`charter-<ISO周>-<序>`（周内唯一·登记面主键·幂等键）——备料 COS 授号；与 tree-id 命名空间分立（tree-id=工作名规范化 kebab 形·同工禁双树——D-27 v10 §5）。
- **来源三路（必填枚举）**：`董事会令`／`需求大表`／`其他`——授号时必填，落头栏「令源」栏＋周索引 charters 条目来源字段（机器可拾取）。
- **时长预估字段**：G0 初判产出（备料 COS 铸条时填·**预估≠裁决**——G1 终裁权=COO·队列深度产能面复核）。
- **周索引 charters 字段**：登记面入周索引 JSON `metadata.charters`（**指针形**：charter-id+原始态件锚+执行域+状态——正文不复制·一处登记多域引用·D-48）。
- **原始态两分离**：任务书原始态=周平面登记面独立件·执行中不迁移不覆写；执行状态随回声更新（状态字段分离·防执行面覆写原始态）。
