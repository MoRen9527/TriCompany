## D1 · 督办读数出单节奏（v1）

### 出单触发面（三型）

| 型 | 触发 | 形态 |
| --- | --- | --- |
| 随件型 | 节点毕报随出督办读数（现役正形·不变） | brief+checkpoint 附毕报 |
| 窗毕型 | 白名单窗毕随出窗毕读数（窗令执行态/止损触发与否/终验锚读数） | 窗毕读数段入毕报·白名单登记面窗行刷毕态 |
| 主动型 | 周期巡检读数——每周一晨首读白名单登记面+候考池出周度督办读数单 | 独立读数单·经 COS |

### 主动型读数单格式（fan-in 呈报正形·并入项）

```markdown
【COO 督办读数单 · <周>·<date 现查原值>】
- 在办件读数表：件/owner/时限/态（达成|在途|逾期）
- 逾期件：逐件逾期时长+升级建议（升级对象+建议动作）
- 白名单窗现势：active 窗读数+当日毕窗对照
- 候考池增量：<本周新增候考项>
- 候裁点：<需 COS/CEO 裁的项·逐条>
```

### 权界沿续（不变）

- 本席出读数单与升级**建议**——分派权/升级权/台账销账变更权不握（⑦ 权界·销账唯 COS·督办结论回写限台账督办字段·排程建议单对 COS 无强制力）。
- 跨周平移预警沿现役：4 周预警、8 周入 CEO escalation（COS 承催办执行）。

## E2 · 残留候考池成文（v1）

### 池正身落位

- `docs/workflow/operating-records/<current-week>/candidates-pool.md`（TriMetaverse 仓）——随周平面迁移滚入新周（跨周未决项平移时逐条带 state）；候选考池必迁件随 LG-053 迁移名录终稿并档（COS 面对表带）。
- 项状态四态沿 CompanyGovernanceRegistry 现行：active / frozen / stale-review / closed（不另起平行状态名）。

### 入池判据（防池变垃圾场）

1. 销账后残留的改进想法/候评估项（原散记 journal/mirror 形态收编）；
2. 观察池≠候考池：观察池=事件观察项（台账承载·有读数锚）——候考池=候考虑的动作建议（本池承载·有建议动作）；
3. 每项必带：一句描述+建议动作+建议 owner+入池时点+状态；无建议动作的不入池（回 journal）。

### 首批收编（现散记候选）

- 观察池「候评估类」④hub-silent 豁免灰度周评估/⑤python 三选候资源读数两项转候考池（带观察锚双挂）；余项留观察池（事件观察类）。
- 其余散记（journal/mirror 残留）候周一晨主动型读数单巡检时逐条收编——首周只立池不强行全量迁移。
