## 一、总则

1. **目的**：为公司全席代码与脚本产出提供统一的审查基准。评审者逐项过审，提交者写码时自对照，审计面以本规范为引用锚。
2. **适用域**：TriCompany 全体席位产出的代码、脚本、CI 配置、工具件。评审形态含：派工验收评审、修复复核、审计抽查、交付前自查。
3. **效力与分工**：
   - 本规范效力由纪律册 D-xx 条锚定（评审必过固定项）。
   - **内容主笔 owner=CTO**：固定项起草、条款解读、随案增补提案。
   - **归域入册 owner=CAO**：本件与纪律册 D-xx 条的批程、授号、生效链。
4. **条款形态声明**：本规范为静态结构化规定，非学习笔记。每条固定项须有案源锚（§二）或增补程序出处（§四）；无案源的条款不入固定项。
5. **两层面分离**：条款的解读、案例讲解、教学材料归各席知识工作区（学习腿）；规范正身只在本件。学习腿材料与正身冲突时，以正身为准。

## 二、评审固定项（首版·四族十三条）

> 用法：评审者逐族过项，任一项不达即退回；提交者交稿前自对照。每条附检查判据与首版案源。

### 族一 · 数据面正确性

- **R1.1 正则与解析字符类覆盖域**：涉及文本匹配/解析的正则与字符类，须核对覆盖域与实际数据域一致——Unicode/中文路径/跨平台分隔符/尾标点等边界显式处理，禁默认 ASCII 假设。
  判据：以仓内真实数据样本（含中文命名件）试跑断言。
  案源：doc-graph-scan R1——`[A-Za-z0-9_\-.]` 不含中文致中文路径引用全漏（2026-10-25 修复：`\w` UNICODE·内链 273→671 边）。
- **R1.2 路径归一边界**：路径归一须区分「前缀剥离」与「字符集剥离」（`lstrip("./")` 系字符集操作非前缀操作）；`..` 中间段须 normpath 处理；越界路径显式丢弃不静默。
  判据：`../` 上级引用、`./` 前缀、混合分隔符三形态各一探针。
  案源：doc-graph-scan R2——`lstrip("./")` 将 `../docs/x.md` 错归一为 `docs/x.md`（2026-10-25 修复：双试归一+越界丢弃）。
- **R1.3 兜底匹配误中面**：模糊匹配/basename 兜底通道须设误中防线——多候选时唯一性守卫或显式标注，禁静默取首。
  判据：构造同名多件场景断言守卫触发。
  案源：doc-graph-scan R3——`endswith("/"+base)` 兜底对仓内多件 README.md 误中（2026-10-25 修复：裸名走唯一性通道）。

### 族二 · 边界与性能

- **R2.1 全量调用耗时上界与失败行为**：全量扫描/全历史调用/跨网络操作须设超时上界，且失败行为（fail-open/fail-closed）显式标注并可归因——禁无界调用、禁失败静默吞。
  判据：超时路径触发一次断言分型输出。
  案源：doc-graph-scan `last_commit_map` timeout=120 + `lastCommitSource` 归因键（2026-10-25 定形）。
- **R2.2 豁免域清单语义**：扫描/处理类的豁免域清单（SKIP 集）须与语义一致——「不作为主体」与「完全不记录」是两种语义，混用即缺陷。
  判据：豁免域内被引用件反向断言（应记录的仍记录）。
  案源：doc-graph-scan SKIP_PARTS 设计——operating-records 不作扫描主体、被引用照记（2026-10-25 定形）。

### 族三 · CLI 工程面（五查）

> 本族五查适用于一切带命令行入口的脚本与工具件。**族源案：doc-graph-scan v2 L184 手搓 argv 解析（2026-10-25 CEO 补审抓出·本席评审漏项·盲区档首例）——CLI 接口面自此独立成族。**

- **R3.1 参数解析规范化**：argv 解析须用标准库（argparse 等），禁手写 `len(sys.argv)` 魔数位次判断。
- **R3.2 未知参数拒显**：错拼/未知 flag 必须报错退出（usage 提示），**禁静默落入默认分支**。
- **R3.3 帮助面齐备**：`--help`/usage 文本齐备，含各参数语义与默认行为说明。
- **R3.4 退出码语义**：成功 0/失败非零，失败不得静默退出 0；脚本可被 CI 与调用方以 RC 断言。
- **R3.5 副作用守卫**：写盘、重扫、外呼等副作用动作**必须显式子命令或 flag 触发，禁止作为默认分支**——错拼静默触发全量重扫+写文件=接口面重伤级缺陷，非 style 项。
  族判据：`--bad-flag` 拒显断言 + `--help` 输出断言 + RC 断言三探针；副作用默认分支专断（裸跑不落写面）。
  族案源：ef61ce00c（argparse 重写+冒烟四绿·2026-10-25）。

### 族四 · 机制接口

- **R4.1 schema 可消费性**：机器产出物（graph/index/manifest/JSON 账本）的字段集须对照下游消费者逐键核对，禁只写不读的自嗨字段。
- **R4.2 漂移检测锚三键**：生成类产物须带 `generatedAt`（生成时刻）、`repoHead`（仓头 hash）、来源标注（生成器路径+spec 指针）三键，供消费面判新旧与溯源。
  案源：doc-graph.json `_meta` 六键定形（2026-10-25）。
- **R4.3 时戳生成正形**：程序内时戳用语言原生物（Python `datetime.now().astimezone()` 系），**禁 spawn 外部 shell `date` 拼接**——进程内生成免环境分叉，带时区。
  案源：doc-graph-scan v2 同族反模式清理（spawn shell date→datetime·ef61ce00c）。

## 三、执行形态

| 场景 | 动作 |
| --- | --- |
| 评审（验收/复核/抽查） | 评审者逐族逐项过，任一不达即退回并引条款号 |
| 写码自查 | 提交者交稿前对照四族自检，CLI 入口件必过族三五查 |
| 审计 | 审计面引用本件条款号为判据锚 |
| 争议 | 条款语义争议归内容主笔（CTO）解读；效力争议归归域 owner（CAO）裁定 |

## 四、随案增补程序（盲区档 → 固定项）

1. **盲区入档**：评审漏项/新缺陷形态经实锚确认后，录 §五盲区档（须含：日期、案件、漏项描述、案源锚——commit/卷面路径）。
2. **提案**：CTO 面将盲区档条目提炼为固定项草案（条款文+判据+案源），入增补提案。
3. **入册**：提案走 CAO 归口批程——通过即入 §二固定项，盲区档条目标「已入固定项」；不采则标「不采+理由」。
4. **形态约束**：每案增补须锚案例来源，**禁无案源扩条**；已入册条款为静态规定，修订走同程序（不因个案临场改条款文）。
5. **节律**：增补随案驱动，无固定周期；批量攒批可并窗（同纪律册铸条窗节律）。
