# 研发技术课程统一讲法

版本：V0.1
日期：2026-06-10
状态：RAndDTrainer 当前统一授课协议初版

## 1. 适用范围

本讲法适用于 RAndDTrainer 当前负责的研发 onboarding、技术 enablement、模块导读、代码导读、工程流程培训、CLI 教学和架构理解课程。

它不替代产品真源、代码真源、registry 或正式设计文档；它只定义技术培训的组织方式。

## 2. 先讲大的结果

每一门研发技术课程，开头先回答四件事：

1. 我们最终实现了什么效果。
2. 这套能力解决了什么问题。
3. 它在项目全局里的位置是什么。
4. 当前成熟度是 MVP、当前可用实现，还是更接近生产级能力。

这一步先让学习者知道“学完之后能得到什么”，而不是一开始就陷进代码细节。

## 3. 再讲理论方法和协议

在说明实现细节前，先把背后的稳定抽象讲清楚。通常至少说明：

- 使用了哪些核心理论方法，例如分层、单一职责、命令分发、状态机、契约校验、source 与 runtime 分离。
- 使用了哪些工程协议，例如参数协议、目录协议、命名协议、manifest 协议、binding 协议、验证协议。
- 哪些是当前项目特定约束，哪些是可迁移到其他项目的通用方法。

课程的目标不是背概念，而是让学习者先知道“为什么要这样做”。

## 4. 先用最小 MVP 跑通一次全流程

讲解顺序优先采用“最小闭环优先”：

1. 只选一个最小可运行场景。
2. 用最少命令、最少输入、最少文件变化跑通一次完整路径。
3. 在每一步说明输入、处理、输出和验证。
4. 让学习者先拿到完整流程感，而不是先背完整实现。

对 CLI 课程来说，MVP 通常是：

- 一条最小命令如何进入 `main`
- 参数如何被解析
- 最小业务函数如何被调用
- 最终产出什么文件、对象或状态
- 如何验证结果正确

## 5. 再由浅入深拆原理

MVP 跑通后，再分层解释：

1. 入口层：程序如何启动，主入口为什么这样写。
2. 参数层：用户输入如何变成结构化参数。
3. 分发层：不同子命令如何路由到不同业务逻辑。
4. 业务层：真正的核心函数、对象和状态变化在哪里发生。
5. 渲染或落盘层：输出文件、对象、目录或外部副作用如何形成。
6. 校验层：系统如何证明自己没有越界、没有写错、没有混层。

这一段的目标是把“能跑”提升为“能解释为什么这样跑”。

## 6. 从 MVP 逐步丰富到当前实现

当学习者理解最小闭环后，再逐步补充真实实现中的复杂度：

- 从单命令到多子命令。
- 从单对象到多类 dataclass 分工。
- 从单文件输出到多文件/多目录输出。
- 从单次成功路径到失败路径、回滚路径和边界校验。
- 从局部脚本到和 agent、support payload、binding profile、manifest、runtime namespace 的协作。

补复杂度时不要一次铺满，而是始终回答：

“这一层复杂度是为了解决哪一个上一版解决不了的问题？”

## 7. 最后讲完整实现和生产级考虑

课程最后再进入完整实现和生产级考虑，通常至少包括：

- 完整函数调用链与类结构。
- 错误处理与退出码设计。
- 幂等、覆盖写保护、输入校验和边界防串层。
- source truth、support payload、runtime state 的职责分离。
- 单元测试、集成验证、帮助命令和回归入口。
- 未来扩展点、当前未做项和明确不承诺项。

这一步的目标不是让学习者死记实现，而是让他知道如何从“会用”走到“会改”和“会扩展”。

## 8. 标准课程骨架

RAndDTrainer 后续默认可按以下骨架组织研发技术课程：

1. 结果：我们实现了什么。
2. 价值：这解决了什么问题，放在全局哪里。
3. 理论：背后的方法、分层和协议是什么。
4. MVP：先跑通一个最小完整流程。
5. 原理：解释 MVP 每一步为什么成立。
6. 增量实现：从最小版逐步长到当前实现。
7. 全实现：完整类结构、函数层级和调用链。
8. 生产级考虑：错误处理、验证、边界、可维护性、扩展点。
9. 总结：学习者最终应记住的几个稳定心智模型。

## 9. CLI 课程套用示例

如果主题是“一个 CLI 如何与 agent 配合完成工作流”，可按下面的讲法展开：

1. 先讲结果：CLI 不是只跑命令，而是把 source 定义、binding、support payload 和 runtime 协作串成闭环。
2. 再讲理论：命令分发、数据建模、契约校验、source/runtime 分层。
3. 然后给一个 MVP：从 `if __name__ == "__main__"` 进入 `main()`，解析一条最小命令并调用一个业务函数。
4. 再拆原理：`argparse`、subparser、dataclass、业务函数、落盘、验证、退出码。
5. 再补完整实现：source kit、publish wrapper、host object generation、binding profile、live entry。
6. 最后讲生产级考虑：幂等、覆盖保护、边界检查、帮助命令、单测、manifest、一致性治理。

## 10. 讲课纪律

- 先讲结果，再讲细节，不倒过来。
- 先给最小闭环，再补复杂度，不一上来压满全部实现。
- 复杂度必须和它解决的问题一起出现，不做无缘由堆料。
- 明确区分“当前已实现”“待验证”“未来扩展”“明确未做”。
- 培训材料必须能带学习者回到真源，而不是替代真源。
- 课程结束时必须沉淀成可复用骨架，供下一门研发技术课程直接复用。
