## 一、设计理据四题

### 1. 为什么维护域用"事件驱动主+定时兜底"双通道，不干脆全自动？

语义与确定性的分权（与 FADE-002"机器永不写摘要"同一价值观的实例化）：
**"哪件事值得记、怎么概括"是语义判断**——做裁决的人记，质量最高，这是事件驱动主；
**"人会不会忘"是概率问题**——确定性脚本每 10 分钟兜一次底，这是巡检。单通道各有死穴：
纯人写=23 小时丢失窗口（旧节奏实测）；纯机器写=没人看得懂的 commit 流水，不是"进度"是"监控"。
双通道靠**单写者三原则**（主叙事权威在人、巡检只追加、冲突退让跳轮）把两种笔迹装进同一份文件。

### 2. 为什么门限用 git 拓扑不用时钟？

`git log <上次触碰>..HEAD` 的 DAG 可达性天然免疫两类时间戳盲区：**同秒提交**（20:20 skip
实测抓出：rebase 连发使 marker 与进度提交同秒，"严格大于"漏计）与**变基重写**（commit
日期被重写后时间戳判据全乱）。教训已从代码层升格为价值观层——D-04 时刻纪律"禁从上下文
时间戳外推"与这是同一条原则的两个投影：**时间戳当参考，拓扑/契约当证据**。

### 3. 为什么推送分两级（sg-bare 必达 / GitHub 尽力而为）？

因为两端的失败语义不同：sg-bare 是**内网必达端**（巡检的直推目标，失败=真故障，如实报
fail 留 recovery push 自愈）；GitHub 是**公网容差端**（服务器无凭据，失败属设计内降级，
≤24h 收敛口径，由事件驱动写收敛补齐）。评分体系为此专设 T5 口径"离线=不可验非 FAIL"——
**失败要分设计内降级与设计外故障，否则兜底通道会被误判为持续故障而失去信任**。

### 4. 为什么迁移域坚持"幂等五步链"而不是一次性脚本？

迁移跑在周日深夜无人值守窗，失败重试是常态而非异常。五步每步幂等（create already_exists
不失败/carry_over 目标存在即 skip）⇒ **失败处置策略=修正后直接重跑**，不需要回滚逻辑、
不需要断点续跑器——用幂等性换掉了整套恢复机制的复杂度。审计面配套：`.shift-ade.json`
五步清单让"重跑到第几步"永远可读。

## 三、今晨三案复盘（2026-09-05，真实教学素材）

### 案 a：良性分叉 union 归账两例——"分叉是双写拓扑的常态，不是事故"

**弧线**：sg watcher 与本机助理双写同一份 daily-progress，跨端推送形成分叉。两例处置：

- **先例**（09-03 凌晨）：sg watcher 02:20 兜底块 b954dffe 与本地分叉 → merge union 归账
  **54294fca**。两笔内伤与对策：①首版 dc8bab38 **误收冲突标记入库**（本地未推即 amend
  修复）——教训=校验断言失败必须中断整条命令链，不许带着红灯继续跑（后升格 D 系纪律）；
  ②commit 附带勘正一条拓扑认知：「watcher 在 sg 检出运行**不受本机脏树影响**」——双写
  两端环境隔离，本机工作区脏不脏与兜底无关。
- **今晨例**（09-04/05 之交）：435188a3（22:30 补写）/a703ea23（00:10 补写）→ 本地 merge
  union 归账 **0335fb62**（双收官叙事+09-05 节并存；**冲突标记 grep=0 验净**——先例教训
  已内化为验收步骤）。

**为什么"良性"**：分叉零丢失——巡检块居前、主叙事殿后、同节去重日期头，双保留合成。
**教训**：双写拓扑下分叉会反复发生，归账不是临时手段而是**纪律**：union 合成+冲突标记
grep=0 验净+归账 commit 留锚。看到分叉第一反应不是"谁搞坏了"，而是"按纪律归账"。

### 案 b：参照系误判勘正案——"结论先于参照系校验，就会冤枉好人"

**弧线**（ledger 09-05 晨检节）：COS 晨检报三 ALERT。ALERT-①「镜像链红：GitHub dev 落后
sg-bare 双仓，sg→GitHub 镜像滞后=新问题」→ 派 CTO 勘。CTO 三线拓扑反转勘定（01:5xZ）：
**sg↔GitHub 零滞后**——sg 工作仓 remote=github 是独立小线自带 watcher，拓扑三线=本机→sg-bare ✓/sg 工作仓→GitHub ✓/**本机→GitHub ✗（hosts 断点）**；「滞后」的真相=**本机 27 笔
推平积压**，sg 侧根本无可修的镜像机制。当日处置：CEO 提权修 hosts 四过期 IP→27 笔清账
（union 归账→push 双向）→三端全平齐。

**同族并发**：ALERT-②「TriMLC-Channel 任务在册缺席」被 BOD 判定先缓——Medium 面查询
而台账早录「SYSTEM 任务 Medium 面不可见」（已知盲区基线未查先断缺席=缺席断言纪律违例
如实认领）；ALERT-③「jobCount=0 vs 预期 1」勘定=陈旧文档预期（0=既证正常态），晨检
cron 连带勘正（新 job 26eacb7b：预期 0+参照系注记+盲区基线禁缺席断言）。

**BOD 裁语**：「晨检参照系教训并入『幻影真源』族=**参照系未验先引用**」——与 FADE-002
幻影真源案（f9a8271）同族：那个案是"引用了不存在的承接段"，这个案是"对着错误的参照系
读数"。**教训**：任何"X 滞后/X 缺席/X 异常"的断言，先验三个前提——参照系本身对不对
（拓扑）、观测工具能不能看见（盲区基线）、预期值是不是现势（陈旧文档）。

### 案 c：relay 断裂旗标体例治理案——"断链不可怕，断链无信号才可怕"

**弧线**：CTO 席两次回报「BOD 未转」——跨席 relay（转呈链）断裂二度发生，关键读数滞留
中途。治理定谳（CTO 表态+COS 采，2026-09-04）：**优先「回报带旗标」体例**——关键锚末尾
统一一行 `[BOD 已转/未转]`（成本最低、零新通道），双席抄送作关键件（终验/收官级）叠加。
CTO 席即起旗标体例，COS 同步采纳。

**与 FADE-001 的关系**：这是**兜底思想在治理面的同构应用**——patrol 对进度文件做
"落后检测+补写"，旗标体例对转呈链做"状态检测+暴露"。两者共同的设计信仰：**任何单通道
都会断，关键不是保证不断，而是断的时候系统自己会喊**。读者在 FADE-002 深度版见过的
"确定性门是新人的同事"，在这里再次成立：旗标就是转呈链的确定性门。

### 三案共性（并入公司教训检查单）

1. **分叉/断裂是常态不是异常**——设计归账与暴露机制（union 纪律/旗标体例），不设计"永不分叉"。
2. **参照系未验先引用=幻影真源族**（BOD 并案裁定）——断言前验拓扑/盲区基线/预期值现势。
3. **断言失败须中断整条命令链**（dc8bab38 冲突标记入库教训）——带红灯继续跑=把校验变成装饰。
4. **环境隔离要写进认知**（watcher 在 sg 检出运行不受本机脏树影响）——别用自己的本地状态推断远端行为。
