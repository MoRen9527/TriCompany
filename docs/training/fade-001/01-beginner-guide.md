# FADE-001 小白版——谁在替你翻工作台、抄工作日志？

## 文档同步元信息

- syncMode: source-only
- lastSyncedAt: 2026-09-05

读者：完全零基础的新人。不需要懂 FADE 协议，不需要读过源码。
目标：30 分钟后，你能说出这个系统每天/每周自动做什么、为什么需要它，并亲手跑通一次自带自测。

---

## 一、一句话说清这是什么

> 公司有一块"工作台"（每周的工作平面）和一本"工作日志"（每日进度文件）。
> **FADE-001 雇了两位不用睡觉的员工：一位每周日晚上 23:00 准时把工作台翻到新的一周
> （旧周归档、新周建好、没干完的活搬过去）；另一位每 10 分钟巡视一次日志，
> 发现没人记就替你补一笔。**

它管两件事，术语叫"双域"：

- **迁移域①** = 周日翻页员（周平面迁移）
- **维护域②** = 每 10 分钟的抄表员（每日工作进度兜底）

## 二、为什么需要它（两个没有它会发生的坏结局）

**坏结局一：周日晚上没人翻页。**
每周的工作计划、待办、任务树都写在"本周目录"里。新的一周开始时，如果没人把上周的
未结事项搬到新目录、建好新周骨架，周一大家就对着旧日历开工——漏事、重事、乱。
以前这事靠人手动搬，现在由河源服务器上的定时任务（cron，"闹钟式程序"）每周日 23:00
自动完成，搬完还留一张"搬运清单"（审计文件）。

**坏结局二：日志只存在于某台机器的内存里。**
公司的工作进展原来记在 AI 员工的"脑子里"（会话上下文）。会话会压缩、机器会重启、
进程会崩——一旦出事，"我们这几天干了什么"就没了。维护域②把一份**粗粒度的工作日志**
（daily-progress.md）随 git 推到三个地方（本地 / sg 服务器裸仓 / GitHub）。
哪怕三点全灭，只要 GitHub 还在，就能把工作重建到最后 10 分钟以内——这是写进登记册的
验收承诺。

## 三、只需要先懂三个词

**1. 周平面（weekly plane）**
"这一周的工作台"：`docs/workflow/operating-records/2026-W36/` 这样的目录，里面放着本周
索引、未结项、任务树。每周一个目录，像日历翻页。

**2. 单写者（single writer）**
日志有两种笔迹：**助理主叙事**（AI 秘书长做完大事随手记，质量最高）和**巡检兜底补写**
（确定性脚本，只在发现"落后了"时补一笔 commit 清单）。规矩：兜底**只追加、绝不改写**
别人的内容；两人撞车时，兜底方退让（重试一次，再不行跳过这轮，下轮再补）。
一台机器补一笔账，永远不会覆盖人的记录——这就是单写者原则。

**3. 兜底巡检（patrol）**
每 10 分钟跑一次的确定性脚本（叫 patrol），它只回答一个问题："日志文件的最后一次更新
之后，仓库里有没有新 commit？"有 → 说明有人干活了但日志没跟上 → 补写；没有 → 什么都不做
（这叫 skip，是正常休息，不是故障）。

## 四、一个比喻贯穿全程

把公司想成一间每周换白板的会议室：

- **周平面** = 白板上这一周的字
- **迁移域①** = 每周日 23:00 的**保洁员**：先把白板整体拍照存档（旧周归档），再擦板画好
  新一周的框（新周骨架），没写完的事项抄到新框里（carry_over），最后在搬运单上签字
  （审计文件 + git commit）
- **daily-progress.md** = 墙上的**值班日志本**
- **助理主叙事** = 值班经理随手记的大事记
- **patrol 巡检** = 每 10 分钟来一次的**实习生**：只准往本子上贴"过去 10 分钟的打卡流水"
  （commit 清单），不准动经理写的字；贴之前先看一眼"上次贴完之后有没有新动静"，没动静
  就安静走开
- **三端持久** = 日志本一式三份（本地/sg/GitHub），烧了哪份都补得回来

## 六、最小体验：亲手跑一次自测（沙箱安全）

前置：能访问 `D:/Code/ai/TriCompany/`（源侧仓库根）。在 **TriCompany 根目录**执行：

```
python -m runtime.cognition.daily_progress_patrol --self-test
```

巡检脚本自带一套验证用例，会在**临时沙箱**里自建迷你 git 仓自测（不碰任何真仓库、
不写任何真文件）。2026-09-05 实测输出：**30 条用例全 `"ok": true`，退出码 0**。
用例覆盖：门限闭合→skip / 门限开→补写 / 自己写完自己不再触发（防自激）/
二次增量只追加不重写 / 单写者纪律检测（补丁里出现删除行要报警）/ 同秒提交回归等。

想再看一眼"只看不写"的真实巡检，可以跑 dry-run（默认模式，不 pull 不写不推）：

```
python -m runtime.cognition.daily_progress_patrol
```

输出一张 JSON 小票：`skip`（门限闭合，日志是新的）或 `would-write`（落后了，会写什么——
`details` 里给将写入的首行预览）。

**验证**：自测退出码 0 + 能说出"skip 是正常休息不是故障"——小白版毕业。

## 七、三个最常见的新人疑问

**Q1：助理反正每次都随手记了，为什么还要巡检兜底？**
因为"人会忘、会忙、会话会断"。事件驱动主保证**记的质感**，巡检兜底保证**记的下限**——
最坏 10 分钟内必有一笔。两者配合才是设计，拆开任何一半都会退化回旧的 23 小时丢失窗口。

**Q2：巡检推 GitHub 失败了，要慌吗？**
不慌，这是**设计内降级**：服务器巡检没有 GitHub 凭据，推 GitHub 是"尽力而为"（失败
不阻塞、不伪造成功）；sg-bare 才是必达端。三端里任何一端可达，日志就不灭——失守的
那端由下一次事件驱动写收敛补齐。

**Q3：周日 23:00 我正在写文档，会被翻页员打扰吗？**
可能会撞上——所以有**迁移冻结窗口**纪律：周日 23:00 前把 operating-records 的改动
全部 commit 并推送，23:00 到周一回流完成期间冻结对 operating-records 的本地写入。
反面教材真实发生过（W34→W35：本地超前 101 个 commit 没推，翻页落在旧底座上，
周一回流被迫人工合并）——纪律是用那次的痛换来的。

## 八、带走的三句话心智模型

1. **周日翻页自动来（迁移域），平时日志双笔迹（维护域）——你只需要遵守冻结窗口**。
2. **兜底只追加不覆盖（单写者），skip 是休息不是故障（门限闭合）**。
3. **日志一式三份，最坏丢 10 分钟（三端持久 + 巡检节奏）**。
