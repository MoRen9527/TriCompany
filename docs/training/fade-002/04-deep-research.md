## 一、架构理据五题

### 1. 为什么一个 CLI 管三域，而不是每域一个工具？

CLI 注释原文（L256-259）："All three CLI scopes serialize to the same top-level envelope
so Score / Close CLI can consume all domains with a single parser and a single validation
schema."——**单一解析器、单一校验 schema**。三个域（目录同步/项目真源/员工发布）业务各异，
但"逐项报告+可守恒+可拒绝"的报告形状是同一个；收口段（Score/Close）因此不用为每域写一套
解析。代价是 CLI 较大（4688 行）；收益是协议四不变量（结构化/守恒/退出码/词表契约化）
只需实现并测试一次。后续新域若不适合 envelope，协议也留了口：经段-实现映射表声明各自
报告合同即可，envelope 只是"发布域参考实现"（spec §2.2，FADE v2.0.0 降格立法）。

### 2. 为什么默认 dry-run、写入要显式开关？

协议 §2.1 关键约束："Agent 不直接执行受治理的副作用或写入终态"；§2.4 安全门："CLI 必须
有 --dry-run 或等效模式（默认不写入）"。落到本 CLI：三个写开关（`--sync`/`--agent-execute`/
`--project-docs-execute`）与 scope 绑死、错配报错（L3894-3899 等）。设计动机是**审计可信**：
如果 Agent 智能环节可以直接写文件，"谁在什么时候照什么改了什么"就不可机械回答。
dry-run 报告里的 `planned_*` action 就是"写意图"与"写事实"的分离表达（L278-279 注释）。

### 3. 为什么 envelope 被当作"合同"而非"日志"？

因为消费方是程序（Score CLI 的 evidence 检索、CI 的退出码判断、台账的聚合读数），程序只能
依赖**不变的形状**。四不变量里最容易被新人低估的是**守恒**（`total == changed + skipped +
errors`）——它让"报告撒谎"变成可判定命题：items 数与 summary 对不上，validation 直接红。
`items` 七字段是基座、域扩展字段只加不改（spec §2.2"消费者状态裁决只可依赖七字段"），
这让域私有信息（tool_drops/candidate/reason）有处安放而不污染共享合同。

### 4. 为什么多宿主渲染模型？复制面与渲染面的张力在哪？

动机（CLI 注释 L105-109）："源单份 + 每宿主渲染模板 → 渲染产物……未来支持任何宿主 =
注册表新增一个条目（模板+目标根+白名单），管线零改动。"live 文件的法律地位是**派生加载壳
（非第二真源）**，所以校验方式是"目标 == render(源+模板)"（`derived_identical`），不是
字节相等——这是 D-07 纪律的机械化。
张力在 **copilot 字节保真复制面**：它承诺逐字节忠实，于是**不能**做 CRLF→LF 归一（渲染面
归一在 copy 透传分支之后，L848 附近的实现顺序是刻意的）；Windows autocrlf 任何翻转都会在
复制面表现为一次假漂移。历史上真实漂过一次（复评卷 enhancement_notes 如实记录）。若要动
这块：归一化复制面会破坏"published-copy 字节级确定性"承诺，正确解法大概率在 git 配置侧
或对比侧，不在复制侧——接手者先想清楚再动手。

### 5. 为什么机器永不写摘要（确定性/语义分权）？

spec §一核心模式："智能发现 → 确定性执行 → 智能审核 → CLI 收口"；反模式表明令"CLI 包含
LLM 推理"。落到 published-summary：摘要内容是小贾（规划）+小乔（产品语义）+小狄（版本与
安全门）的**语义产物**，以候选文件形式喂入（`--project-doc-candidate ID=PATH`），CLI 只做
元信息四门校验（sourceOfTruth/syncMode/sourceRevision/lastSyncedAt，L1690-1710）然后复制。
宁可长期 `requires_candidate`（partial），不越权生成一个字。这条分权是整条管线"可审计"的
前提：确定性环节的回答永远可以复算。

## 三、协议与实例的共生循环

- **实例喂协议**：runId"单一显式标识优于分散组合"（spec §2.8 细则 5）的括号实证就是本实例
  的复评弧线——首评 run_id 时间戳派生（7 分，卷宗引用只能反查时间戳），复评显式命名
  （`fade-leftover-20260821-b1-claude-recheck` 一眼可读，10 分）。定位成本的差异就是那 3 分。
- **协议保护实例**：细则 10"接线+实测才算立法完成；纸面法两次周检未接线即冻结退回"——
  本 CLI 的纪律（改完必跑校验套件）与此同源：stdout 是机器合同，改形状不跑
  validation = 只做了纸面修复。
- **评分是证据的函数**：复评 93 分里 `terminal-sample` 仍是 8 分没回修——manifest
  `adeLifecycle` 如实标 pending，不为"好看"抬分。诚实低计是这套评分制度能被信任的原因。

## 四、三案复盘（2026-09-04/05 发布实战）

> 三案均发生于同一批真实发布窗（LG-024 session 面渲染 × LG-028 真源减法 × M-001 注入）。
> 原始记录：TriMetaverse `.fade/hub-snapshots/ledger-mirror.md` LG-024 条；commit 双仓可查。

### 案 1：字节漂移——"check=True 申报不实"（TriMetaverse fe60f355）

**弧线**：LG-028 第二步"CLAUDE.md 真源减法"发布窗。发布执行后自检申报 check=True 通过；
随后发现发布面带排版漂移（TriMMC 对齐空格差异+File Conventions 节空行位次偏移），
当夜返工 fe60f355 以真源 body **全量覆写**并逐字节终验=零。

**双重缝根因**（commit 原文自录）：① 校验脚本**只比行数未逐字节**——判据本身不实，
"行数一致"放行了"内容位次漂移"；② TriMMC 排版修后重写发布面时，位次偏移**未再校验**——
修一处漏一处。

**立法收口**："逐字节比对为唯一判据"随批入册（CAO 3b380a3 批量入册中以 **D-16 byte-exact
再证判例注**承载，不另立条防凑数）。此后每次发布以逐字节零为收官读数：82babd95
（TriLC→TriRLC 双名并书勘误）即管线发布 in_sync 逐字节零实证；LG-028 收官锚
（fe60f355 系→CEO session 正签件再渲染 f3afbb69）同口径。

**教训**：表面成功 ≠ 实际正确（"200 不作数"纪律同族：表面指标全绿、实质为零/漂移）。
**判据本身必须被审计**——你用什么证明"没漂移"，比"没漂移"的结论更重要。

### 案 2：幻影真源——「合同真源 D-04」悬空引用（TriCompany f9a8271）

**弧线**：M-001 状态条头部机械合同的注入通道立法为 **a-lite**：管线**运行时读取** D-04
纪律册正身、抽取 M-001 段、注入全部 13 席 session 面。批 2 渲染窗前置，FSD 实勘发现：
**D-04 正身根本没有 M-001 段**（"状态条"全文零命中）——而手抄两版段源（CEO 席/CHO 席
session-body 各一份）段尾都标着「合同真源 D-04」。引用是真的，被引用物不存在：**悬空引用**。

**为什么这案价值高**（BOD 判语升标题级）：「悬空引用若非管线真读正身，将长期潜伏」——
如果当初立法采"复制常量注入"，两份手抄段会被复制进 13 个文件，错误从"引用悬空"
升级为"13 处假真源"，且再没人会去正身找答案。**单源教义的黄金正例**：管线坚持运行时
读取正身，才让缺位在第一渲染窗就暴露。

**修复（两步解耦）**：裁 a 案先入册再抽——CAO 将 M-001 段成文入纪律册正身（f9a8271，
D-04 v5：CEO/CHO 双版逐字一致抽验+FSD 供料同文；段位置刻意放 D-17 后独立段，适配抽取
正则的段体边界）。工程侧**早有降级语义**：正身段缺位=跳过注入+stderr 警告，渲染不炸
（CLI L242-246 注释、L754-756 实现）——入册前不阻塞生产，入册到位自动生效。
终核：M-001 投影段+尾注 13/13 命中（b149952）。你若在岗，本会话 system prompt 里的
"状态条机械合同"段尾那句「合同真源：D-04（运行口径演进见台账 M-004/M-001 注记）」
就是修复后的活体产物。

**教训**：引用必须可解析——写「真源在 X」之前，先验 X 里有承接段；**运行时读取优于
复制常量**（复制体即漂移面+1）。

### 案 3：写根 bug——"修假设，不是修参数值"（TriCompany 3200b89）

**弧线**：LG-024 批 1 渲染窗（11 席源件新建）。新建源件产生真实 diff、触发真实写入，
文件却落在了**幽灵目录** `D:\Code\ai\.claude\hub\`（工作区根，而非 TriMetaverse 仓内）。
FSD 勘定+正位覆盖+幽灵清扫；CTO 令面自认表述错误，FSD 照令无责。

**根因**：写根实现用了 `source_root.parent`——M0e 勘定令表述"同级 layout 下 parent 即
TriMetaverse 根"在数学上就是错的（`TriCompany` 的 parent 是 `D:\Code\ai` 工作区根，不是
兄弟仓）。这是**layout 假设**错误，不是笔误。

**为什么潜伏了两代**（本案最值钱的部分）：M0e 期 18 件目标 `identical 跳过`未真写——
skip 路径**隐含"目标已存在"的假设**，bug 无从暴露；直到出现"新建源件+目标不存在"
的组合才真写爆发。前科在册：M0e 再生窗 0fcd4cc 已同族发作过一次（当时钉了 manifest
前缀，但 layout 假设本身没动）。批 2 窗还三现同族读数（`skipped_identical=5` 但渲染件
实不存在——后经 FSD 新鲜实勘消解为旧态读数，验前时点教训入 D-19）。

**修复（b 案根治）**：`_resolve_agent_target_path` 改 **manifest 前缀感知**——target 带
`TriMetaverse/` 前缀→live 根=调用方显式传入的 `source_root.parent / "TriMetaverse"`；
无前缀→support_root（现行 CLI L791-828，调用点 L1503-1514 注释载完整弧线）。否决 a 案
"layout 硬编码换位"——换位即碎。BOD 裁语：「b 案消除 layout 假设系根治非补丁，
0fcd4cc 同族二次发作证明**该修的是假设本身**」→ 教训升格 **D-20（修假设非修参数值）**。
验收五条含 BOD 增补的**负路径多级 layout 场景**（防三犯），回归护栏=测试三件
（validation L675/L705/L720）。连带清出 `.github\agents` 面 19 件幽灵（M0e 错位写根
多面积累），TriMetaverse 真源 live 面全程未动。

**教训**：第一，修 bug 修的是**假设**不是参数值——参数值改对了假设还在，必然二次发作；
第二，skip/identical 这类"表面无事"路径要专门问一句"它无事是因为真无事，还是因为没看"。

### 三案共性（收敛成可复用的检查单）

1. **表面成功 ≠ 实际正确**：行数判据/identical 跳过/200 响应——凡"通过"，先问判据是什么。
2. **判据与引用本身要被审计**：byte-exact 唯一判据；「真源在 X」必须 X 可解析。
3. **修假设非修参数值**（D-20）：二次发作=假设没修的信号。
4. **证据判读先验时点与通道**（D-19）：旧态读数会冒充现状缺陷。
5. **管线的价值恰在于此**：三案都不是人眼发现的——字节漂移被逐字节终验门拦下、幻影真源被
   "运行时真读正身"暴露、写根 bug 被发布窗真实写暴露并由负路径测试钉死回归。
   **确定性门是新人的同事，不是官僚主义**。

## 五、开放问题与演进方向（接手者会遇到的）

- **事件自动写入增强**：event-watch 检测面已落地，"检测→自动执行写入"挂 automation-backlog（CTO 2026-08-21 裁决）。设计约束已立：project-docs 永不自动写（摘要类必须候选+联审）。
- **Plan/Close Skill 结构化装载**：manifest `adeLifecycle` 如实标 pending——规划与终裁仍是人工联审态。结构化前，"发布窗口"的语义由角色分工承载（见[产品版](02-product-guide.md)旅程 A）。
- **宿主注册表条目化**：新宿主=加一条 HostRenderSpec，管线零改动（已验证：claude-session 即此路径的产物）；宿主**退役**机制未立法（agent-governance-alignment-design 挂 CEO 定调待办）。
- **复制面行尾张力**：见§一第 4 题——这是设计张力不是待修 bug，动之前先想清楚破坏什么承诺。
- **渲染层不做语义 hack**：LG-024 双行残留案的裁语可作原则引用——"渲染层 hack 源侧脏数据"劣于"源侧清残+重渲"；管线只忠实投影，不替真源遮丑。
