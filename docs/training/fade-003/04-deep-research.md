## 一、设计理据五题

### 1. 为什么"记周记"这种小事需要一条流水线？

因为立册前的翻车**不是文笔问题，是制度问题**：跳过规范查找/跨周找旧模板/内部台账入册
（spec §三 反模式三条，全是实录）。共同根因=**"记什么"有人判，"怎么记、记到哪"没人管**。
FADE-003 的回答：把后半句全部机械化（格式=CLI 渲染/落点=当周路径校验/去重=begin+append
双拦/脱敏=双扫）——写什么继续靠人（四问+语义裁决），怎么写交给确定性。这与全协议的
分权哲学同源，但它的特殊价值在于：**发生在最小、最日常的动作上**——小事立规矩，是制度
成熟度的试金石。

### 2. 为什么 Close CLI 是校验者而非发起者？

两处机器否决的实案给出了回答：

- **否决一**（runId 541da30c，2026-08-25）：agent 裁 approved，机器查 run 链不过→先
  ESCALATED，补齐后第二次 close 才 APPROVED。日志两行俱在。
- **否决二**（代码 L290-293）：`--verdict approved` 而链上最近 score=FAIL → 自动降级 retry，
  终端原话"agent 裁 approved 但评分未达线（最近 score FAIL）——校验者裁 RETRY"。

设计语义：**语义裁决（好不好）是 agent 的领地，CLI 永不代做；但裁决的**前提条件**（链齐不齐/
达没达线）必须机器复算**。agent 的 approved 是"主张"，CLI 的 APPROVED 是"经校验的主张"——
两者之间的差距，就是这套系统能被审计的原因。

### 3. 为什么 S 满分 80 是地板、W≥10 是最小裁判权？

登记册历史档案行写得毫不留情：升档前"**Score CLI/Score Skill 双段缺失（质量评价缺位）=
W34 首写违规 D-06 的制度根源**"——没有评分段的流水线，写坏也只能事后人眼看。所以升档时
机检部分做成**必选地板**（S1-S7 全过，omission≠0 直接 FAIL），语义部分做成**最小裁判权**
（W≥10，即 100 分制里语义至少占一成话语权）。升档联审明文"**80 卡线史是教训不是基准**"——
首评 80/100 卡线通过的教训直接写进了及格线设计。

**代码层的精确语义**（接手者必辨）：CLI verdict 条件=`allPass && (total===null || total≥90)`
——W 未合并时机检 PASS 即 PASS（total===null 通道），W 地板靠**流程约束**（Close Skill 语义
裁决+首 3 功能期 run 双席抽验）而非代码强制。这不是缺陷，是"代码强制/流程约束"分层的自觉
选择——但要改这行，先读升档联审裁定原文。

### 4. 为什么只追加不重写，还要配 S7 守恒基线？

周记的法律地位=**已签发的对外口径**（P3：豁免仅限 CEO 明确指令与 run 链 revision 授权的
本次条目）。实现上三层防线：append 的 revision 链检查（无授权行→REJECTED）→ score 的
S7 守恒基线（非本 run 条目 diff 零变化，期望集=run-log 全历史 APPENDED/REVISED 最新 title，
changed_others/unregistered 逐个点名）→ close 五查。**授权链全程机器可校验**——"别人签发
的东西绝对禁区"从纪律变成了代码。

### 5. 为什么升档走"补段不重构"？

升档五销账（LG-013）全部是**追加段**：Score CLI=正典链追加段（"begin/qualify/append/close
既有逻辑零改动，close 增分支不重构"——spec §2.5 载体裁定原话）；Score Skill=CLI 之外的自评
json 合并；RETRY=close 增一个分支。配套映射声明：**静态固化域的 Plan 时点=载体定版时点**——
与 FADE-001 扩维卷两先例同一原则两投影（无逐次 Plan 的实例，冻结点取载体定版 commit 同盘）。
设计哲学：**已验证的链路是资产，升格=长出新器官，不是换心脏**。

## 三、98 分弧线复盘（runId 7a85e3e0）

- **素材本身是个教训**："内存存活掩盖重启必炸——dist 生产形态服务的潜伏损坏与诊断路径"
  （W35 周记 2.2）——素材出自 LG-012 crash loop 实战（TriModel dist 丢失潜伏损坏，进程内存
  存活掩盖了磁盘损坏直到重启）。**好周记的素材往往是刚付过学费的地方**，这条是范例。
- **分数构成**：S1-S7 机检 80/80 满分（omission: false）+W 自评 18/20（各 0-5 四维，双席抽验
  在案）=98。丢的 2 分在语义维度——机检满分+语义留缺口的分布，恰证"地板+裁判权"设计的
  意义：机检保证下限，语义区分上限。
- **卷面纪律**：升格卷双 hash raw=lf 相等=纯 LF 无漂移——SOFT-DRIFT 教养在评分卷上的体现；
  冻结三要素（载体定版同盘+canonical 算法+卷值不入卷防自引用）与 FADE-001 扩维卷同构。

## 四、教训收敛四条（并入公司检查单）

1. **缺的段是制度根源，不是疏忽**——W34 违规的根因登记为"Score 双段缺失"，修复=补段而非
   写检讨；制度缺陷要用制度补。
2. **卡线不是基准**——80 卡线 PASS 的教训直接升格为及格线设计（90 含 W≥10）：从失败里读出
   的参数，比拍脑袋的阈值可靠。
3. **机器否决要留痕**——两处否决 agent 的实案全在 run log（ESCALATED 行+降级 retry 的终端
   提示+logRun 记录 agentVerdict 原值）：否决可追溯，被否决方才有改进依据。
4. **引用表述要与实盘对表**——registry 对自家"run log 完整审计链"表述的自我勘误注记
   （08-20）：发现表述超前于实盘，改表述不改史实，勘误注记留痕。与"数字断言对实盘"检查单
   同族（本系列小白版 CHO 抓的槽位/树计数两犯同源）。

## 五、开放问题与演进

- **触发自动化四项**（backlog）：自动建草稿/对话后自动判断追加/周六午前更新/签发提醒——
  实现后走同一套 CLI 与规则，人工与自动化不双轨（spec §四 明文）。
- **FROZEN 留口**：词表三态（APPROVED/ESCALATED/RETRY）中 FROZEN 被裁"留口正名后扩值"
  （细则 10：无场景的态=纸面态）——等真实冻结场景出现再立法。
- **W36/W37 无新册**：手动触发下的自然节奏；"有值得记的才记"vs 周期性沉淀的张力候验。
- **自评到双席抽验的过渡**：--skill-json 的 W 分目前是 agent 自评+首 3 功能期 run 双席抽验
  常设——抽验常态化与否、自评防伪机制候评。
